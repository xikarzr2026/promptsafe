Privacy & Data Handling

This page describes the browser app's data flow and its limits. It is a technical summary, not a legal-compliance certification.

Processing and storage

Pasted text: The browser app processes text in the current tab. Its first-party code does not transmit or persist the text while scrubbing. It does not use cookies, local storage, session storage, IndexedDB, or analytics.

Hosted access: When served from GitHub Pages or another host, that provider receives the initial page and static-asset requests and may log IP address, time, and other request metadata under its own policies. A local copy loads only local assets.

Limits: Secret and PII detection is pattern-based and incomplete. Review the sanitized output before sharing; do not treat PromptSafe as a guarantee that every sensitive value was found.

This page describes the browser app's technical behavior; it is not a legal certification or compliance guarantee. The optional CLI, REST server, and browser extension have separate data flows and security requirements.

Accounts and hosting

The browser app has no account system and does not submit pasted text to a PromptSafe backend. The static hosting provider may process access metadata such as IP address and request time.

For requests about hosted access logs or deletion, contact the hosting provider. For the local copy, closing the page ends the app session, but PromptSafe cannot guarantee forensic erasure from browser or operating-system memory.

Technical Architecture

Static browser app: The browser interface is static HTML, bundled CSS, and first-party JavaScript. It has no third-party runtime scripts or build-time dependency for normal use.

Optional tools: The repository also contains a CLI, a separately configured REST server, and a browser extension. They are distinct programs and have separate permissions; do not assume browser-page privacy statements apply to them.

Storage: The browser page does not use cookies, local storage, session storage, or IndexedDB. Reversible-redaction keys intentionally contain original values and may be copied to the system clipboard; Clear All removes the in-page key and derived output.

Network: The browser app makes no outbound HTTP(S) request while processing text. Custom regexes run in an in-memory blob: worker. When hosted, the initial HTML and local static-asset requests go to the hosting provider, which may keep access logs.

Open source: The complete source code is available on GitHub under the MIT license. You can audit, fork, and self-host the static files.

Verify It Yourself

Don't take our word for it. Here is how to verify our privacy claims in under a minute:

  1. Open your browser's Developer Tools (F12)
  2. Select the Network tab and clear it
  3. Paste text containing secrets into PromptSafe
  4. After local assets finish loading, watch the Network tab while scrubbing — there should be no processing requests
  5. Set throttling to "Offline" and keep scrubbing — the already-loaded app should continue to work
  6. Read the HTML, CSS, and JavaScript assets from the repository
